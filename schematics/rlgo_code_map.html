RLGo Code Map

How the scripts and functions in this repository fit together: the training loop that improves the bot, the batched search inside every move, the library layers underneath, and the ways a trained bot is served to a person or another program.

One training iteration

Everything starts from play_train_eval_zero.py main(). It runs the four stages below in a loop. Each stage starts fresh worker processes, and the stages talk to each other only through files in the work directory.

Inside one move: a batched search round

ZeroAgent.select_moves searches every game a worker is playing at the same time. The trees stay separate, but each round's new leaf positions from all of them go to the network in one call. That shared call is the only step that runs on the GPU.

Library layers

Each layer only calls the layers below it. Teal chips are on the Zero training path. Dashed chips are earlier code from the Deep Learning and the Game of Go book that this pipeline doesn't use.

Deployment and visualization

A trained .hdf5 agent reaches the outside world in three ways: a browser board through Flask, any GTP program through standard input and output, and a static Elo chart from the training run.

Known gaps

  • Web board: you can't pass or see a score in the browser, and you always play Black. The bot plays until the board is full.
  • run_gtp.py serves a policy-network bot from the book (agents/betago.hdf5, also missing), not the Zero agent, and its first line still names Python 2.
  • eval_zero.py is an older copy of the training script that still plays one game at a time.
  • Training data: each round trains only on the newest batch of self-play games. There's no replay window of recent games.
